**The release is like for like again.** The planner's priors were left at v0.56's and every record of v0.57 was built again under revision 52 from its own regeneration data. Of v0.57's 136 pictures, 113 came back to the pixel; 22 were drawn again or moved, each with its own templates; one was replaced; and two probes were added. So this screen is a second reading of 113 pictures and a first of the mended ones, picture for picture.

## The benches

Every reader was a fresh subagent given the screen's own reader prompt and its pictures and nothing else. The record is `vision/isolation_v058.md`.
- **A reader in one arm only.** v0.57 had found that a count by arm can be a reader's habit. So in both rounds a reader had a row's pictures in one arm, and the arms crossed between the rows: every count can be given by reader as well as by reading.
- **Round 1.** Twenty-three of v0.57's pictures were built again on their own records' plans with only the new drawings changed, in up to three arms: as v0.57 drew them (beside the screen's own reading), with the new drawing, and with an alternative. 120 readings by 15 readers; five analysts who never saw a picture counted each row from the readers' own lines.
- **The wheel was not the fault.** The same line stood in the unsure section of every arm: "- The wheelbarrow's wheel looks like a square frame with spokes rather than a round wheel, which is odd." And the inventory had: "- Red wheelbarrow (centre, front): parked, empty." So the barrow was drawn again as the bicycle had been in v0.56, with somebody at it.
- **Round 2.** Sixteen readers, 128 readings: the barrow parked and wheeled ("Its wheel is a square, not a round wheel, so it could not roll properly."), the kite's reel in the hand and on the grass, and the heavy seesaw's new man with v0.57's child and with the new one ("The seesaw is tipped down toward the man, which fits him being much heavier.").
- **What the benches cannot show.** Other readers read each arm, and the wheeled barrow also stands in another place of its picture. And a bench is not a screen: the kite's gain on the bench, 24 of 34 for 7 of 16, is three pictures of six with a hedge in the screen, as before.

## Key words, frequency and age of acquisition


Unchanged from v0.20: every item record carries its key word's Zipf frequency (f, for things and actions only) and its
age of acquisition (a, from the bundled excerpt of Kuperman, Stadthagen-Gonzalez and Brysbaert, 2012) at weight 0;
`scenegen/norms/aoa_kuperman2012.tsv` keeps the citation and source in its header and every record stores its sha256.
The licence note and what the pilot should test are in the v0.20 README section of the same name (the CC BY-NC-ND 3.0
question about shipping an excerpt; the model with AoA against the model without, pre-registered; AoA kept varying apart
from frequency when choosing the pilot's pictures). Before the pilot, check the bundled rows against the original file
(`python -m scenegen.difficulty --check-aoa <the original .xlsx or .csv>`).

## How to run

```bash
python -m venv .venv && source tools/env.sh      # from Git Bash on Windows too
pip install -r requirements.txt                  # the cast needs Blender 5.2.3 LTS: installed, or pip install bpy==5.2.3 on Python 3.13

python assets/cast/build_cast.py assets/cast/out058                 # build the cast (under a minute)
cd assets/cast && python gapcheck.py out058 person.kai && cd ../..  # check one character's poses for parts that come apart
python -m scenegen.generate --tier 3 --setting playground --seed 7 --out scenes
python -m scenegen.generate --from-record __REBUILD_EXAMPLE__ --out tpdb_work/check   # exact rebuild
python -m scenegen.reach --out reach.json                          # the poses the templates can ask for

python -m scenegen.batch showcase --out scenes
python -m scenegen.calibrate --out calibration.json
python -m scenegen.difficulty --check-aoa <the original Kuperman et al. file>   # compare the bundled AoA rows
python -m scenegen.combos --out combos.json
TPDB_TRIP48=O python vision/isolation_bench.py tpdb_work/bench tpwN_1 tpwN_2   # one template alone, cropped (here with revision 44's trip)
python vision/prepare_screen.py scenes,probes vision/v058   # then describe and score: vision/screen_prompts.md
bash tools/cycle/summarize.sh                               # add the screen to vision/screen_summary.json
python vision/gate.py vision/v058 scenes,probes
python -m scenegen.site --scenes scenes --gallery assets/cast/gallery058 --old-gallery <v0.57 renders of the same variants> \
    --combos combos.json --screen vision/screen_summary.json --out site
python3 package_release.py 0.58 --single   # the release as one zip, tpdb_v0.58.zip
```

The release is one zip, `tpdb_v0.58.zip`, about __ZIP_MB__ MB. Google Drive does not virus-scan a file over 100 MB, so it asks to confirm the download ("can't scan this file for viruses"); the file downloads as normal after that. `package_release.py` checks, file by file, that the zip holds every file of the release. Without `--single` it writes the same release as zip parts under 50 MB each, with the README and the set's pictures beside them, for browsing in Drive.

Exact rebuilds hold within a release: a v0.57 record rebuilds with the v0.57 package. They also depend on Pillow, pinned in `requirements.txt`: Pillow 13 resamples RGBA differently from 12, and every embedded asset changes. A different cairo moves a few pixels by one level and leaves the SVG identical. Renders from an installed Blender differ from the Linux module's only in sub-pixel anti-aliasing on the outlines, with identical anchors and geometry, so the library mixes the two.

## Known limits

- The weights are still the spec's starting values: every predicted completeness is a placeholder
  until the pilot fit.
- The blind screen used AI readers. It is a filter for illegible drawing; the pilot with people
  remains the test of difficulty.
- __LIMITS__
- The cast is a stand-in. Final character art would replace the models; rigs, poses, faces,
  anchors and manifests carry over.

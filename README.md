# TPDB v0.52: sleeves that are cloth round an arm, on v0.51's own set; 63 of 64 templates through the gate, read a forty-ninth time

v0.51 ended with every template through the gate and a list of what read least well. Sam's brief for v0.52: "Go for v0.52 and fix up upper arms, shoulders, and sleeves!" It names how the figures look, so the work is the cast's drawing, judged large and in pairs before anything else, and the list (`vision/flaws_v051.md`) stands beside it.

What v0.51 drew, on sheets of all ten people at twice the release's size (`vision/isolation_v052.md`): a tee's sleeve was a cap that ended above the armpit in a rounded end, narrower than the arm it held and with no hem, and the arm stepped out wider under it; raised, the arm went up bare from a stub of cloth at the armpit; and a long sleeve was one thick tube from a round shoulder to a rounded end at the wrist.

The work is in the cast alone (builder 0.52.0), behind one switch whose letter O gives v0.51's drawing (`TPDB_SLEEVE52`). The placement rules are revision 48's, unchanged.
- **A tee's sleeve** is cloth round the arm: as wide as its wearer's own arm and a little more, tapering a little to a hem that is cut straight across the arm, with the arm coming out of it.
- **A long sleeve** tapers from the shoulder to an open cuff a little above the wrist, on the hooded top, the cardigan and the shirt under the waistcoat.
- **A sleeve goes with its arm**: raised, an arm carries its sleeve up with it.
- **The shoulder's ball** is where it was. Moved or resized by a few millimetres it broke one figure's body (below).
- **Put to readers and not taken:** the sweeper standing nearly upright (v0.51's O1). In ten whole pictures the sweeper was read as grown with either pose.
- **Looked at and left:** the walker's ice cream (R2), which is at the mouth already. **Not worked:** the rest of v0.51's list, which is scene drawing and placement and stands for v0.53.

The set was regenerated and screened a forty-ninth time, and it is v0.51's set with the new figures in it: every one of the sixteen cells, the five isomorphs and the 81 probes placed on v0.51's seed with v0.51's templates, and in the set's 21 pictures the same people stand in the same places to within 12 px. The answer keys are v0.51's item for item.

The forty-ninth screen read 102 pictures, the set's 21 and 81 probes, with thirteen readers and four scorers: 1,095 of 1,114 scored items had full marks, and none was misread. **63 of the 64 templates pass the legibility gate, and `square_wheel` does not**: 0.812 in its eight pictures, because two readers of the four wheelbarrows did not notice the wheel and a third named the bicycle's back wheel only among the things it was unsure of. The wheel is the scene's drawing and no line of it changed; the three pictures are the three in which v0.51's readers named the wheel only in passing. Because the set is v0.51's with other figures in it, the screen is also a second reading of v0.51's pictures: 1,054 of the 1,114 items have the score they had, 50 of the 60 others are the clouds or a tree that a reader left out or named, and ten are not, seven of them lower and three higher. Of the 19 items under full marks, twelve are the clouds or a tree; four are the wheelbarrow's, one the bicycle's, one the thief bird's and one the bread's. Nothing was mended, swapped or read again after the screen, so the count is the first and only one. The set's score rose to 0.986, from 0.976. On the strict count 54 of the 64 templates pass, for v0.51's 56. No reader of a whole picture wrote of a sleeve, a shoulder or an arm as drawn, in this screen or the last: the new drawing was judged where it shows, large and in pairs, and chosen there by 10 reviewers of 12, 10 of 12 and 4 of 6. The four grown figures are called young first in 5 of their 85 pictures, as in v0.51.

Everything is built by code and reproducible: the cast is modeled and posed in Blender (Blender 5.2.3 LTS), and the scenes are composed in SVG by the generator in `scenegen/`. From v0.24 the whole cycle also runs on Windows with an installed Blender (`RUNBOOK.md`, Setup).

Every set of four is made in both orders. Thirty reviewers in all: the new drawing was chosen by 10 of 12, 10 of 12 and 4 of 6, and given 34, 35 and 13 figures to v0.51's 9, 9 and 7.

## How to run

```bash
python -m venv .venv && source tools/env.sh      # from Git Bash on Windows too
pip install -r requirements.txt                  # the cast needs Blender 5.2.3 LTS: installed, or pip install bpy==5.2.3 on Python 3.13

python assets/cast/build_cast.py assets/cast/out052                 # build the cast (under a minute)
cd assets/cast && python gapcheck.py out052 person.kai && cd ../..  # check one character's poses for parts that come apart
python -m scenegen.generate --tier 3 --setting playground --seed 7 --out scenes
python -m scenegen.generate --from-record scenes/T3_park_s8023.json --out tpdb_work/check   # exact rebuild
python -m scenegen.reach --out reach.json                          # the poses the templates can ask for

python -m scenegen.batch showcase --out scenes
python -m scenegen.calibrate --out calibration.json
python -m scenegen.difficulty --check-aoa <the original Kuperman et al. file>   # compare the bundled AoA rows
python -m scenegen.combos --out combos.json
TPDB_TRIP48=O python vision/isolation_bench.py tpdb_work/bench tpwN_1 tpwN_2   # one template alone, cropped (here with revision 44's trip)
python vision/prepare_screen.py scenes,probes vision/v052   # then describe and score: vision/screen_prompts.md
bash tools/cycle/summarize.sh                               # add the screen to vision/screen_summary.json
python vision/gate.py vision/v052 scenes,probes
python -m scenegen.site --scenes scenes --gallery assets/cast/gallery052 --old-gallery <v0.51 renders of the same variants> \
    --combos combos.json --screen vision/screen_summary.json --out site
python3 package_release.py 0.52 --single   # the release as one zip, tpdb_v0.52.zip
```

The release is one zip, `tpdb_v0.52.zip`, about 427 MB. Google Drive does not virus-scan a file over 100 MB, so it asks to confirm the download ("can't scan this file for viruses"); the file downloads as normal after that. `package_release.py` checks, file by file, that the zip holds every file of the release. Without `--single` it writes the same release as zip parts under 50 MB each, with the README and the set's pictures beside them, for browsing in Drive.

Exact rebuilds hold within a release: a v0.51 record rebuilds with the v0.51 package. They also depend on Pillow, pinned in `requirements.txt`: Pillow 13 resamples RGBA differently from 12, and every embedded asset changes. A different cairo moves a few pixels by one level and leaves the SVG identical. Renders from an installed Blender differ from the Linux module's only in sub-pixel anti-aliasing on the outlines, with identical anchors and geometry, so the library mixes the two.
